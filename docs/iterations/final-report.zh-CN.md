## 一句话说明

把项目里已经跑通四轮的那套「按一句话找剧照 → 批量抓候选 → 编号拼图让视觉模型挑帧 → 裁字幕／叠字幕 → 精选 + 全量双文件夹交付」，改造成**任何一个 AI 助手下载后都能直接用**的独立技能包，按"能上传到 GitHub 的高分项目"标准打磨，一共做了**三轮完善和自检调试**。

原来的那套只在这台机器、这个项目里能用：它引用项目内部文件、写死了本机 Python 路径、依赖登录过的工具，脚本也散在别处。现在这些都去掉了。

打开自媒体项目，进 `03 工具与技术`，就能看到 `still-finder` 这个文件夹。完整绝对路径我在对话里告诉你；报告里不写本机路径，是为了保证这个文件夹**不含任何私人信息、可以直接公开**。

### 哪些东西不在这个文件夹里（重要）

这次工作还牵涉到一些东西，它们**刻意没有**放进技能包：

1. **项目原资料**：四轮攒下的技术档案、原始脚本、900 多张素材、流程文档和台账 —— 原样留在项目里，一张没搬。里面有你的私人路径和真实剧照，不能进公开仓库。技能包里带走的是**方法**，不是素材。
2. **本轮真实联网下载的真剧照**：全部放在系统临时目录，没放进技能包，也按"不删任何候选"的规则**没有删除**。
3. **这次工作的反馈记录**：追加在项目台账和项目记忆里，属于内部记录，不属于开源包。
4. **上传动作本身**：没做。

所以准确说法是：**技能包本身全在这一个文件夹里；这次工作涉及的其他材料仍在它们原来的位置。**

## 五、最快怎么用

```bash
# 1) 装依赖（只装 Pillow）
python -m pip install -r requirements.txt

# 2) 先探测：现在哪些源能连（免费、免登录）
python scripts/still.py probe

# 3) 抓候选，会生成编号拼图和来源清单
python scripts/still.py grab --out ./work \
  --page "https://movie-screencaps.com/avatar-2009/page/114" \
  --image-referer "https://movie-screencaps.com/" --limit 40

# 4) 打开 work/contact_1.jpg，用眼睛或视觉模型看，记下选中的编号
# 5) 交付（把 picks.json 里的编号改成你选的）
python scripts/still.py deliver ./work --picks picks.json --out ./delivery
```

完全不想联网也能跑通：见 `examples/quickstart.md` 的离线自检一节。

⚠️ 源会变。每次开工先跑 `probe`，别照搬文档里的示例网址。本机默认的 `python` 如果没装 Pillow，要用"装依赖的那个同一个解释器"来跑，否则会报找不到模块。
